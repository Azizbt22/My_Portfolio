01 / Context

Retrieval gives a model evidence. It does not guarantee faithfulness.

A standard RAG system can retrieve a relevant passage and still add a fluent statement that the passage never supported.

The project studied grounded answering with small open models. The central question was whether structured prompting could improve faithfulness and refusal behaviour without fine-tuning.

Expected behaviour

Answer from retrieved documents, expose claim-level support and refuse questions outside the corpus.

Experimental question

Does verification help every small model equally, and which model property predicts success?

02 / Reliability challenges

Why grounded generation still fails.

The system must coordinate retrieval, generation, verification and abstention. A failure at any stage can produce a confident unsupported answer.

ConstraintMechanismImpact

01Retrieval noise

The closest chunks may be related to the query without containing the answer.

The model can treat topical similarity as evidence.

02Fluent hallucination

Language models complete plausible statements from prior knowledge.

An answer can sound correct while exceeding the retrieved context.

03Answerability

The system must detect when the corpus cannot answer the question.

A forced answer creates false confidence on out-of-domain queries.

04Evaluation

Exact lexical overlap penalises valid paraphrases; semantic similarity can accept vague claims.

Faithfulness needs complementary signals and calibrated thresholds.

04 / Design choices

One model, several explicit roles.

A single underlying LLM performs planning, grounded generation and claim verification through separate structured prompts.

01 / Shared model

Control cost and comparison

Every role uses the same candidate model, making model behaviour the main experimental variable.

02 / Explicit roles

Separate planning, answering and checking

Role boundaries improve inspection and make failure analysis more precise.

03 / Evidence constraint

Close generation around retrieved text

The answer prompt requires support from the supplied context and includes an abstention path.

04 / Claim-level checks

Evaluate atomic statements

Individual claims reveal partial support that one answer-level similarity score would hide.

05 / Architecture

The verification-aware RAG workflow.

The question passes through five responsibilities. Each stage leaves an output that can be inspected independently.

01 / PLANQuery plannerCheck answerability and frame retrieval intent.
02 / RETRIEVEFAISS searchReturn the four closest passages.
03 / GENERATEAnswer writerRespond from retrieved context.
04 / DECOMPOSEClaim extractorSplit the answer into atomic facts.
05 / VERIFYClaim scorerMeasure support and assign a verdict.

06 / Dataset and protocol

A small benchmark built to expose failure modes.

The corpus contains six machine-learning articles and five physics articles. Five unrelated questions test whether the system refuses unsupported requests.

237 chunks

Documents were segmented into 500-word chunks with a 50-word overlap.

384 dimensions

MiniLM embeddings were indexed with exact FAISS Flat L2 search.

07 / Faithfulness scoring

Combine semantic and lexical evidence.

Each extracted claim is compared with the retrieved context through five complementary metrics.

35% semantic similarity25% ROUGE-L20% ROUGE-210% BLEU10% word overlap

Claim support

A combined score of 0.18 or above marks a claim as supported. The threshold was tuned to accept paraphrases.

Answer verdict

PASS begins at 0.40 faithfulness, PARTIAL at 0.25, FAIL below 0.25. A valid refusal receives ABSTAIN.

08 / Results

09 / Interpretation

The architecture depends on instruction-following ability.

Qwen 1.5B gained 21.4 points while the larger code-focused Phi-2 lost 15 points. Model size did not explain the difference.

Meta-instructions matter

Verification requires a model to follow staged instructions, assess support and choose abstention.

Baseline affects gain

The strongest improvements appeared where vanilla faithfulness left more room for correction.

Verification has a cost

Planning, generation and checking require three model passes for every question.

Self-verification is a model capability to evaluate experimentally, not a guarantee created by adding a prompt.

10 / Limits and next tests

Strong controlled results with a narrow scope.

The experiment used a small English corpus, five compact models and empirically tuned thresholds. The result describes this controlled setting.

Broader corpora

Test multilingual and high-stakes domains with more varied document structures.

Larger models

Measure whether explicit verification still helps models above three billion parameters.

Stronger calibration

Tune thresholds on a held-out set and add human faithfulness judgements.
